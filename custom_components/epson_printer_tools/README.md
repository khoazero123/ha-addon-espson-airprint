# Epson Printer Tools — Home Assistant custom integration

Native HA entities for the **Epson Printer Tools** add-on. The integration talks to the
add-on REST API over HTTP and does not use MQTT, so it can run alongside the existing
MQTT discovery entities without touching them.

## Requirements

- The add-on running and reachable from Home Assistant, e.g. `http://homeassistant.local:8099`.
- The API token generated by the add-on (stored server-side as `/data/api-token`,
  surfaced in the add-on UI). The integration sends it as
  `Authorization: Bearer <token>` on every request and never logs it.

`GET /healthz` stays public in the add-on; the integration only uses
`GET /api/state` (validation and polling) and `POST /api/action`.

## Install

1. Copy `custom_components/epson_printer_tools/` into your HA config directory
   (`/config/custom_components/epson_printer_tools/`).
2. Restart Home Assistant.
3. **Settings → Devices & services → Add integration → Epson Printer Tools**.
4. Enter the add-on URL (default `http://homeassistant.local:8099`) and the token.
   The form validates by calling `GET /api/state`; a rejected token shows
   *"The add-on rejected the API token"*, an unreachable host shows
   *"Could not reach the add-on API"*.

## Entities

| Entity | Type | Source |
|---|---|---|
| Status | sensor | `printer.state` (IPP 3 idle / 4 processing / 5 stopped), `unreachable` when the printer is not reachable |
| Pages printed | sensor | `usage.pages_total`, `total_increasing`, unit `pages` |
| Last print | sensor (timestamp) | `usage.last_print` |
| Last clean | sensor (timestamp) | `usage.last_clean` |
| AirPrint | binary sensor (connectivity) | `airprint.enabled` and a queue being present |
| Nozzle check | button | `POST /api/action {"action":"nozzle_check"}` |
| Head clean | button | `POST /api/action {"action":"head_clean"}` |

Status sensor attributes: `raw_state`, `reasons`, `reachable`, `model`, `serial`,
`server_time`, `last_poll`. AirPrint attributes: `queue`, `ipp_uri`, `error`.

Device: manufacturer Epson, model and serial taken from the add-on state,
`configuration_url` = add-on URL. Entity unique IDs are derived from the config entry ID,
so renaming entities in the UI is safe.

## Options

`Settings → Devices & services → Epson Printer Tools → Configure` changes the URL, the
token and the poll interval (15–3600 s, default 60). Changing the URL re-validates the API
and rejects a URL already used by another entry.

## Availability semantics

- API unreachable, timeout, non-200 response, or invalid JSON → coordinator update fails →
  all entities become `unavailable` (last data is kept internally, no stale values shown).
- HTTP 401/403 during polling starts a reauth flow in HA.
- Printer reported not reachable → Status shows `unreachable`; other entities keep their
  last known values.
- Missing fields (e.g. no `pages_total` before the first SNMP poll) → `unknown`.
- Button press failures raise a visible `HomeAssistantError` with the add-on error text.

## Diagnostics

`Settings → Devices & services → Epson Printer Tools → Download diagnostics` returns the
entry data, coordinator metadata and the last state payload. The token is replaced with
`**REDACTED**`.

## Tests

```
python3 -m py_compile custom_components/epson_printer_tools/*.py
python3 custom_components/epson_printer_tools/tests/test_mock_client.py
```

`tests/test_mock_client.py` runs without Home Assistant installed: it stubs the few HA
symbols the coordinator uses and exercises the real HTTP layer against a local aiohttp
server (Bearer header, `/api/state`, `/api/action`, 401 → reauth/`UpdateFailed`,
500 → error surfaced, unreachable host → `UpdateFailed`, action whitelist, partial state).

## Known limitations

- Auth header is assumed to be `Authorization: Bearer <token>`. If the add-on ends up
  using another scheme or header, only `coordinator._headers()` needs updating.
- No SSL verification override: use plain HTTP on the LAN (the add-on serves HTTP).
- No reconfiguration of the add-on itself; printer IP, AirPrint and MQTT stay managed by
  the add-on UI/options.
- `history` from the API is not exposed as entities.
- Polling interval is a minimum of 15 s; the buttons refresh the coordinator after
  the job is accepted, and the add-on re-polls the printer itself.
